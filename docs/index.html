A helpdesk API with a triage worker.

Customers open tickets. Agents move them from open to closed. A Celery worker assigns a category, a priority, and a suggested first reply — from an OpenAI-compatible model, or from keyword rules when no API key is set.

Django 5.2 Django REST framework JWT Celery + Redis PostgreSQL

Run it with docker compose up --build, then docker compose exec api python manage.py seed_demo. Swagger lives at /api/docs/ on the API process. This page is the short version; the full schema is the ReDoc reference.

Who can see what

RoleTicketsWrites
customer Only their own. Other ids are 404. Open a ticket, comment in public, edit title and description while it is open.
agent The whole queue. Status, priority, category, assignee, tags, and internal notes.
admin The whole queue. Everything an agent can do, plus delete tickets and tags.

Seeded passwords are Ticketdesk-demo-1 for admin, sam, riley, alice, bob, and carol. Registration always creates a customer.

Status workflow

open→ in_progress→ resolved→ closed

resolved can return to in_progress. closed can return to open. Any other jump is a 400. Customers cannot change status.

Illegal transition

curl -s -X PATCH http://localhost:8000/api/tickets/9/ \
  -H "Authorization: Bearer $AGENT" \
  -H 'Content-Type: application/json' \
  -d '{"status":"closed"}'
{"status": ["Cannot transition from in_progress to closed."]}

That 400 was measured after the ticket had already moved from open to in_progress. Closed is only reachable from resolved.

Triage without a key

Empty LLM_API_KEY skips the network and uses keyword rules: billing, access, technical, account, then general. Words such as outage or down force priority urgent. With a key, the worker calls POST {LLM_BASE_URL}/chat/completions, retries timeouts and 429/5xx with backoff (1s, 2s, 4s), then stores the keyword result if the model still fails.
